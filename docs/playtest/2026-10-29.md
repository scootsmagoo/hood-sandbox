## Findings

1. **Soak fails: the bot never gets a map tile to drive on** (high confidence on cause, not reproduced in the working copy)
   - Log: `the bot failed: SyntaxError: Unexpected token '<', "<!doctype "... is not valid JSON`
   - Log: `1 page error(s): pageerror: Unexpected token '<', "<!doctype "... is not valid JSON`
   - Log: `the bot drove only 0 m/min (stuck?)`
   - Likely cause: `public/tiles/` is in `.gitignore` (baked tiles, "regenerate with: cd tools/pipeline && npm run bake"). The fresh clone has no `public/tiles/`, so the default tile request (`tiles/atlanta/m1-five-points/` per `src/main.ts` DEFAULT_TILE) hits the dev/preview server's HTML fallback, and the JSON parse fails. The working copy at `~/Documents/projects/hood-sandbox` does have `public/tiles/atlanta`, which is why this is an environment gap rather than a game bug. Not verified against the soak harness internals.
   - Not changed: regenerating tiles needs the bake pipeline and its inputs, and no code fix is clearly justified by this one finding.

2. **Soak and controls report the failure poorly** (suggestion)
   - The soak reports a raw JSON `SyntaxError` instead of "map tiles missing, run the bake". A preflight check for `public/tiles/<default>/` would turn this into a clear message.

## Suggestions (for the owner, not implemented)

- Consider making the soak's "driven 0 m" a separate message from "the bot failed", so the two causes are not conflated.
