## Findings

- **F1 (soak, FAIL):** `hood-playtest-2026-11-11.log` line 875: `the bot failed: SyntaxError: Unexpected token '<', "<!doctype "... is not valid JSON`. Line 876 repeats it as a page error. Likely cause: the dev server returned the `index.html` fallback for a tile JSON request. `public/tiles/` is gitignored build output (see `docs/deploy.md`), so a fresh clone has no baked tiles. The controls run says the same thing: "no baked tile in public/tiles: skipping the real-tile check". This is inferred from the log and the missing folder, not reproduced in a separate run.
- **F2 (soak, FAIL):** line 877: `the bot drove only 0 m/min (stuck?)`. This is a consequence of F1. The bot never got a tile to drive on, so this is not evidence of a stuck car.
- **F3 (noise):** the soak log has 807 lines `file watcher error: ENOSPC: System limit for number of file watchers reached` from the Vite dev server (the controls log has more of the same). The inotify limit on this host is 524288, so the cause is probably a per-user instance limit or other watchers on the machine. Not a repo bug. Lowering the noise needs either `--dist` (serve the built output) or a host setting, which the bot does not change.
- **F4 (coverage gap):** the controls check skipped its real-tile checks (police escalation, real-tile), so those controls ran only on synthetic scenes.
- **No errors found** in the vitest or typecheck or build output. `grep` for `Uncaught`, `FAIL`, `warn`, `stuck` in the test and build logs shows nothing beyond the run summaries. The only `warn` lines were npm install-script notices for `workerd`, which are not repo code.

## Suggestions (not code changes)

1. Add a preflight to `scripts/soak.mjs` and `scripts/controls-check.mjs` that checks `public/tiles/atlanta/` exists and exits with a clear "run `npm run bake` first" message. Today the soak reports a JSON parse error instead.
2. Document in `docs/` (or the README) that a fresh clone must bake tiles before the soak, so nightly runs can use a baked tile set.
3. For nightly runs, consider `--dist` on the soak so the Vite watcher is not started (it floods the log with ENOSPC).
4. Once tiles are available in the nightly environment, the soak's drive check (60 m/min) is the most useful signal. Re-run it before judging drive or stuck behaviour.

## Not covered

This bot does not judge gameplay feel, difficulty, handling, or design. It checks crashes, errors, frame cost, memory growth and scripted progress. Anything about how the game feels to play needs a human.
