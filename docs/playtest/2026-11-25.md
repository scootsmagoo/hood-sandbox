## Findings

1. **Soak fails on a fresh clone with no baked tiles (environment, not a game regression).** Seen in the first attempt today and in yesterday's log (`hood-playtest-2026-11-24.log`):
   - `the bot failed: SyntaxError: Unexpected token '<', "<!doctype "... is not valid JSON`
   - `1 page error(s): pageerror: Unexpected token '<', "<!doctype "... is not valid JSON`
   - `the bot drove only 0 m/min (stuck?)`

   Cause: `public/tiles/` is in `.gitignore` and is absent from a clean clone. The dev server answers the tile request with the SPA `index.html`, and the JSON parse fails. With the tiles present the same commit passes. The same failure has appeared on most recent nightly runs (PRs #8 to #12).

2. **Vite file-watcher ENOSPC spam in every run (noise, does not fail a gate).** `hood-playtest-2026-11-25.log` has 2643 lines of `file watcher error: ENOSPC: System limit for number of file watchers reached`. The controls log has none. The host's `fs.inotify.max_user_watches` is 524288, so the limit being hit is probably a different inotify limit (for example max_user_instances) or the dev server watching too much. Harmless for the verdict, but it hides real errors in the log.

3. **Bot idle at start and one stuck event (informational).** `walked 0 m` for the first ~0.5 min, and `stuck` reaches 1 at 0.75 min and stays at 1 for the rest of the run. The soak does not fail on this (progress is judged on metres driven per minute, 216 m/min here, against a floor of 60).

4. **Single sim-step spike (informational).** `sim step max 36.72 ms` at 8.00 and 8.25 min. Frame p95 stayed at 16.67 ms and slow frames stayed at 0, so this did not show as a dropped frame in the bot's sampling.

No failing tests, no `Uncaught` errors, and no `warn` lines in the soak or controls logs apart from the ENOSPC noise in finding 2.

## Not covered

The bot checks crashes, errors, frame cost, memory growth and whether it keeps moving. It does not judge gameplay feel, design, balance, or whether the map looks right. Those need a human playing.

## Suggestions

- **Make the soak fail with a clear message when `public/tiles/` is missing** (before starting the bot), instead of the cryptic JSON error. Or document in the README that the soak needs `npm run bake` (or a copied `public/tiles/`) in a fresh clone. This would stop the same nightly FAIL from recurring.
- **Quiet the Vite watcher in the soak and controls runs** (ignore `docs/`, `public/`, `tests/` and similar, or lower the watcher count), so real errors are easier to spot in the logs.
- **Log the reason for each bot stuck event** to see whether the idle start and the single stuck event are a bot routing issue or a real road/collision problem worth a look.
